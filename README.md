# job-research · 快速蒸馏

> **投之前，30 分钟判断这个岗位值不值得投。**

求职里最贵的错误不是简历写得差，是**花了两个星期去投一家不该投的公司**。这个工作流先做判断，再做材料——判断错了，材料写得再漂亮也没用。

一套写给能读写本地文件的 Agent 用的求职决策工作流：读 JD 和公开信息 → 拆公司、拆岗位 → 给「投 / 条件投 / 不投」+ 3 条理由 + 3 个风险 + 1 条反转条件 → 要投的话，再出一页方案和一段能直接发出去的话。

---

## 你现在卡在哪一步？

| 你手上有什么 | 你会说 | 30 分钟后你拿到 |
|---|---|---|
| 一张 JD 截图，别的都没有 | 「快速判断这个岗位」 | `00_快速判断.md`：投不投 + 3 理由 + 3 风险 + 1 反转条件（**不打匹配分**，没你的数据不打分才诚实） |
| JD + 一份简历 | 「快速蒸馏这家」 | 01 公司蒸馏 + 02 岗位蒸馏（含匹配度评分）+ 04 证据附录 |
| 决定要投了 | 「写投递方案」 | `03_投递方案.pdf`——A4 单页，能直接发给 HR |
| 不知道第一句怎么开口 | 「写个打招呼话术」 | `05_投递动作包.md`：一段纯文本、复制就能发的首条话术 |
| 面试通知来了 | 「准备面试」 | `06_面试包.md`：作答框架 + 反向面试 + 谈薪 + 入职 90 天 |
| 不投，但想把这家公司研究透 | 「练习轨：只研究不投」 | 按信息价值定深度，沉淀可迁移的业务规律 |

> 只给 JD 也能跑。缺什么会在开头列缺口，不会硬编。

## 它会交付什么

| 文件 | 内容 | 什么时候有 |
|:--:|---|---|
| 00 | 用户诊断 / 快速判断 | 第一次用做一次，之后复用 |
| 01 | 公司蒸馏（五层：广度/宽度/深度/高度/决策） | 全部 |
| 02 | 岗位蒸馏（JD 反拆 + 硬门槛 + 匹配度评分） | 全部 |
| **03** | **投递方案（对外 A4 单页 PDF）** | S/A 必做 |
| 04 | 证据附录（每条结论标证据等级 + 口碑三面） | 全部 |
| **05** | **投递动作包（首条话术，可直接复制）** | 要投就做 |
| 06 | 面试包 | 受邀后 |
| 07 | 复盘与校准 | 投递/面试后 |

分级：S ≥85 / A 75–84 / B 60–74 / C <60；边界 ±3 取低档。**分级是我给你的判断，不是结论**——真正的交付物永远是「今天能不能发出第一句」。

## v4 加的四把刹车（这是它和普通求职模板的区别）

一般的求职工具都在帮你**多产出**。这个工作流主要在帮你**少犯错**：

| 机制 | 干什么 | 为什么需要 |
|---|---|---|
| **口碑三面** | 用人面（待得下去吗）/ 用户面（产品能打吗）/ 行业面（正不正经）分开查 | 单看一面会误判：只用人口碑差可能是「强度大但合法」，只看用户口碑差可能是行业通病。**至少两面出现同一负面才进结论** |
| **一号位画像** | 创始人/实控人 + 直接对外发声的高管：三句带日期的原话、关键决策、**反例 1–2 条** | 「0 篇专访」本身就是判断依据，要写明；实控人不露面 + 法人另有其人 → 写风险，不写人格 |
| **判断与表达自检** | 交付前三问（我编了吗 / 对方会怎么解读 / 我是不是替他做了立场判断）+ 断言三标 | 把「推断」写成「事实」，是这类文档最致命的错 |
| **检索语法** | 锁定主体、招股书 PDF、行政处罚 `site:gov.cn`、裁判文书、离职口碑、一号位原话 | 同样 10 分钟，命中率差好几倍 |

## 安全边界（它不会做什么）

- **不编造经历**：只写用户档案里真实存在的经历；公司业务 ≠ 个人职责。写不出来就把那一格空着。
- **不把数据当亮点**：数据是门槛不是亮点。话术里不出现「数据 / SQL / 看板 / 指标口径」这类词。
- **不替用户辩解**：「其实是接手运营的，不是我从零搭的」这种话只在对方向起时说，不主动写进首条话术。
- **不自动投递**：不登录、不点「立即沟通」、不发任何消息。所有对外文本由用户自己复制发送。
- **不猜硬性条件**：学历、年限这类死门槛拿不到就标「待确认」，不假设。
- **缺料会降级，不会装**：拿不到的数据标「未取得」并写清搜了哪几个平台。

## 安装

核心：把 `SKILL.md` 当主提示词，`references/` 和 `examples/` 作为它引用的资料，放到 AI 能读到的位置。

| AI | 放哪 |
|---|---|
| Claude Code | `~/.claude/skills/job-research/`（复制整个目录） |
| Codex | `~/.agents/skills/job-research/`（用户级）或项目内 `.agents/skills/` |
| DeepSeek Harness | Skills Manager 导入，或复制到 `~/.dsh/skills/job-research/` |
| 其他 | 把 `SKILL.md` + `references/00_蒸馏标准.md` + JD 一起粘进去（只能走快速判断，文件写入和联网会退化） |

**运行前提**：文件读写 + 联网搜索。没有 PDF 工具不影响判断，只交单页 Markdown。

**隐私**：发简历前遮掉手机号、身份证号、住址、前客户名；诊断文件里用代号。

## 触发方式

装了 skill 的模型会自动判断要不要用。人话就够：

- 「快速判断：<公司名>，<岗位名>」——只要你判断，不要八件套
- 「快速蒸馏：<公司名>」——要完整八件套
- 「这家公司怎么样」「这岗位值得投吗」「拆一下这个 JD」
- 「帮我写投递方案」「写个打招呼话术」
- 「帮我准备面试」「怎么谈薪」

> 「快速判断」和「快速蒸馏」是两个不同粒度，别混：前者只出一个文件，后者走完整流程。

## 方法论一句话

广度（行业）→ 宽度（信息）→ 深度（判断）→ 高度（视角）→ 决策（8 步推演 + 机会成本）。评分 = 匹配 40% + 薪资 20% + 健康 20% + 主线 20%，可复算。校准闭环：决策日志 → 结果回填 → 每 5 家校准。

## 免责

基于公开信息 + JD 推断，产出是「假设版」判断，不是内部数据。每个结论都标了证据等级，投递决策请结合面试验证。
