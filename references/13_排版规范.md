# 13 · 输出排版规范

> 目的：让每份产出 **10 秒抓到重点**——结论最前、风险有背景色、判断有颜色、数字加粗、对比用表格。
> 适用范围：所有 00–07 文件（Markdown 层）+ 03 投递方案（HTML/PDF 层）。

## 一条总原则

**读者 10 秒扫一遍，就知道「结论是什么、风险在哪、哪句能信、下一步干嘛」。**
先结论 → 再证据 → 再推论。禁止资料堆前面、结论藏最后。

---

## 〇、颜色字典（本项目的标色体系）

> 这是 job-research 自己的标色体系，不是抄别家的。根子是我们方法里最核心的**四层语义区分**——**信息（事实）/ 判断（结论）/ 洞察（反共识）/ 决策（行动）**，外加一层**假设（未验证）**。
> 颜色 = 语义的**固定标签**。**一种颜色永远只表达一种意思，8 个文件里不换。**

### 1. 行内色标（短语级）

| 颜色 | 色值 | 语义 | 标什么 |
|---|---|---|---|
| 🟢 绿 | `#27ae60` | **证据 / 事实** | 有来源的数据、量纲验算通过、一手材料、已核实 |
| 🟠 橙 | `#d97b29` | **判断 / 结论** | 该不该投、匹配等级、北极星、一句话结论 |
| 🔴 红 | `#c0392b` | **风险 / 死门槛** | 否决项、红线、硬门槛不满足、处罚、离职潮 |
| 🟣 紫 | `#7d3c98` | **洞察 / 反共识** | 有张力、反共识、认知打破的判断 |
| ⚪ 灰 | `#7f8c8d` | **假设 / 待验证** | 我的假设、未取得、待核实、低置信度、口径警告 |

写法：`<span style="color:#d97b29">**该投，A 级**</span>`

规则：
1. **只标「关键短语」，不整句、不整段**（整段标 = 没标）。
2. **每千字 ≤ 8 处**，宁精勿滥，每处都是真重点。
3. 颜色叠加在**已经加粗**的短语上（颜色是加粗的强化，不是替代）。

### 2. 块级背景色（callout，Obsidian + GitHub 都渲染）

> 这是「背景色重点标记」的主力——**一整个块高亮，一眼扫到**。

| Callout | 语义 | 用途 |
|---|---|---|
| `> [!important]` | 🟠 核心判断 / 结论 | 一句话结论、该不该投、北极星 |
| `> [!danger]` | 🔴 风险 / 死门槛 / 红线 | 否决项、硬门槛不满足、处罚、离职潮 |
| `> [!tip]` | 🟢 可执行动作 | 下一步、可练动作、面试要做的 |
| `> [!note]` | 🔵 证据 / 事实 / 口径 | 来源、验算、五级口径、定义 |
| `> [!quote]` | 🟣 洞察 / 反共识 | 有张力的判断、认知打破 |
| `> [!warning]` | ⚪ 假设 / 待验证 | 我的假设、待核实、低置信度 |

规则：
1. **每个文件第一屏必须有 `> [!important]` 一句话结论**（强制，不是可选）。
2. **风险 / 死门槛必须用 `> [!danger]` 包住**，不许平铺在正文里。
3. 一处一义，不混用。

### 3. 行内背景高亮（`<mark>`，Obsidian + GitHub 都渲染成黄底）

用于「长句里最不能漏掉的那一个词 / 数字」：

> 豆柴 2026 目标增长 <mark>**50%**</mark>，但大盘只有 **+5.9%**。

规则：`<mark>` 只用在一句话里最不能漏掉的那一个词，一屏 ≤ 3 处。

## 一、Markdown 层（00/01/02/04/05/06/07 日常阅读）

### 1. 一句话结论置顶
每个文件第一屏，用 `> [!important]` + 加粗，不超过 3 行。

> [!important] 结论
> **豆柴值得投，A 级条件投**——岗位招的是「用户经营」，你缺的只有宠物行业经验（可补救）。

### 2. 风险 / 状态三级色标（emoji，跨平台兜底）

| 标记 | 含义 | 用在哪 |
|---|---|---|
| 🔴 | 死门槛 / 硬风险 / 直接否决 / 已证伪 | 死门槛、红线、打分里 ≤40 的维度 |
| 🟡 | 待核验 / 有条件 / 低置信度 | 待 JD、假设未验证、条件投 |
| 🟢 | 已验证 / 达标 / 可投 / 高置信度 | 达标项、已核实的事实 |
| ⚠️ | 注意 / 口径警告 / 假设 | 口径差异、数据警告 |
| ✅ / ❌ | 对照表里「过 / 不过」 | 交付前对照表 |

规则：**「风险 / 死门槛 / 待核验」前面必须带 🔴 或 🟡；「已验证 / 达标」前面带 🟢。** 颜色（span/callout）是 Obsidian 里的强化，emoji 是任何平台的兜底，两者都要。

### 3. 结论性数字一律加粗
评分、金额、增速、百分比、阈值、日期——凡是「读者会拿来做决定的数字」，必须 `**加粗**`。

- ❌ 豆柴复购率 65%，2026 目标增长 50%。
- ✅ 豆柴复购率 **65%**，2026 目标增长 **50%**。

### 4. 表格优先于段落
对比、清单、打分、推演链、口径——用表格，不用长段文字。一个格子里不塞两个信息。

### 5. 交付前对照表（每文件末尾强制）

| 检查项 | 是否达标 | 证据 / 位置 |
|---|---|---|
| 洞察 ≥2 条且过三检验 | ✅ | 3.2 节 |
| 评分可复算 | ✅ | 5.2 节 |

### 6. 标题与长度
- 用 H1–H4，不用 H5/H6；每层标题下第一句必须是结论句，不是「下面讲……」
- 长度上限（超了就拆到 04 证据附录，正文只留结论）：

| 文件 | 上限 |
|---|---|
| 00 用户诊断 | 100 行 |
| 01 公司蒸馏 | 300 行 |
| 02 岗位蒸馏 | 150 行 |
| 03 投递方案 | 80 行（A4 一页） |
| 04 证据附录 | 120 行 |
| 05 动作包 | 120 行 |
| 06 面试包 | 150 行 |
| 07 复盘校准 | 80 行 |

### 渲染差异（必须知道）

- **Obsidian**：span 色 + callout 背景 + `<mark>` 全部渲染，效果最好。
- **GitHub**：callout（`> [!note]`）渲染成浅色块、`<mark>` 渲染成黄底；`<span style="color:…">` 被剥离（降级为普通加粗，仍可读）。
- 所以：**核心信息永远用 callout / emoji / 加粗承载（跨平台）；span 颜色只做 Obsidian 内的视觉强化，不承载唯一信息。**

## 二、HTML / PDF 层（03 投递方案）

03 是对外文档（发 HR / 面试官），走 HTML + Chrome 印 PDF，上真颜色。

- **结构**：顶部一句话定位（色块）+ 三层结构 + 90 天 + 指标 + 我的假设 + 一句「为什么现在」。
- **配色**：沿用上面的颜色字典——🟠 橙 = 定位/北极星 · 🔴 红 = 我的假设里可能出错处 · 🟢 绿 = 指标/达标 · 🟣 紫 = 差异化洞察 · 中性灰 = 正文。**5 色 + 灰，各司其职，不超 6 色。**
- **排版**：A4 一页、页边距 7mm/9mm；表格斑马纹；每个 section 一条色块标题。
- **命令**：`Chrome --headless=new --no-pdf-header-footer --print-to-pdf=<out> file://<html>`；用 `pdfinfo` 验 Pages=1。
- **禁止**：面试问题、内部评价、竞品贬损、薪资谈判、公司「做错了什么」——这些留在对内文件（02/04/06/07）。

## 三、退稿线（排版不过 = 退稿）

交付前自查，任何一条不满足就退回重写：

1. 没有 `> [!important]` 一句话结论（🔴 一票否决）。
2. 风险 / 死门槛 / 待核验没带 🔴 / 🟡，也没用 `> [!danger]` 包住。
3. 结论性数字没加粗。
4. 该用表格的地方用了长段文字。
5. 末尾没有交付前对照表。
6. 颜色用错语义（绿标了风险、红标了事实），或整段标色。

## 四、示例与模板必须自证（v4.5 新增，这条最容易被跳过）

> 上一轮的教训：规范写了 13 条，示例一个都没照做——模型学到的是"规范是建议"。**示例是模型唯一的模仿对象，示例不合规 = 规范作废。**

1. **每个模板顶部必须有「排版契约」块**：结论块占位 + 色标图例 + 行数上限 + 对照表要求。模板不承载规范，模型就不会写。
2. **每个示例必须过本文件全部 6 条退稿线**：`examples/` 下任何一个文件不合规，先修示例，不许只改规范。
3. **示例里的结论块必须写在第一屏**（前 15 行内），不许放在文末。
4. **对外文件（03/05 话术）禁止出现未核验事实**：用了就加"据公开报道，如与实际情况不符请纠正"，并在 04 证据附录标 🟡 待核验。
5. **快速判断模式（无简历）** 的排版：首屏一句话结论（值得去 / 有条件去 / 不建议去 + "不含个人匹配"），3 条支持 + 3 个风险（🔴🟡），1 条反转条件；**不得出现任何分数**。

## 五、自查脚本（最低成本的一致性检查）

交付前在仓库根目录跑：

```bash
# 1) 每个 01/03 是否有一句话结论块
for f in examples/*/01_*.md examples/*/03_*.md; do
  grep -q "\[!important\]" "$f" || echo "缺结论块: $f"
done

# 2) 行数上限
awk 'FNR==1{print FILENAME}' examples/*/01_*.md | while read f; do
  [ "$(wc -l < "$f")" -le 300 ] || echo "超 300 行: $f"
done

# 3) 正文是否有色标
for f in examples/*/01_*.md examples/*/03_*.md; do
  grep -q "🔴" "$f" || echo "正文无色标: $f"
done
```
