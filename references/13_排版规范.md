# 13 · 输出排版规范

> 目的：让每份产出 **10 秒抓到重点**——结论在最前、风险有颜色、数字加粗、对比用表格。
> 适用范围：所有 01–07 文件（Markdown 层）+ 03 投递方案（HTML/PDF 层）。

## 一条总原则

**读者 10 秒扫一遍，就知道「结论是什么、风险在哪、哪句能信」。** 先结论、再证据、再推论；禁止把资料堆在前面、结论藏到最后。

---

## 一、Markdown 层（01/02/04/00/05/06/07 日常阅读）

Markdown 原生没有颜色，视觉重点靠下面 6 样，**任何平台（Obsidian / GitHub / VS Code / Notion）都生效**。

### 1. 一句话结论置顶
每个文件第一屏，用引用块 + 加粗，不超过 3 行。

> **结论：** 豆柴是……岗位招的是……（不是……）

### 2. 风险 / 状态三级色标（emoji）

| 标记 | 含义 | 用在哪 |
|---|---|---|
| 🔴 | 死门槛 / 硬风险 / 直接否决 / 已证伪 | 死门槛、红线、打分里 ≤40 的维度 |
| 🟡 | 待核验 / 有条件 / 有风险 / 低置信度 | 待 JD、假设未验证、条件投 |
| 🟢 | 已验证 / 达标 / 可投 / 高置信度 | 达标项、已核实的事实 |
| ⚠️ | 注意 / 口径警告 / 假设 | 口径差异、数据警告 |
| ✅ / ❌ | 对照表里「过 / 不过」 | 交付前对照表 |

规则：**每个「风险 / 死门槛 / 待核验」前面必须带 🔴 或 🟡；每个「已验证 / 达标」前面带 🟢。不许只给文字不给颜色。**

### 3. 结论性数字一律加粗
评分、金额、增速、百分比、阈值、日期——凡是「读者会拿来做决定的数字」，必须 `**加粗**`。

- ❌ 豆柴复购率 65%，2026 目标增长 50%。
- ✅ 豆柴复购率 **65%**，2026 目标增长 **50%**。

### 4. 表格优先于段落
对比、清单、打分、推演链、口径——用表格，不用长段文字。一个格子里不塞两个信息。

### 5. 交付前对照表（每文件末尾强制）

| 检查项 | 是否达标 | 证据 / 位置 |
|---|---|---|
| 洞察 ≥2 条且过三检验 | ✅ | 3.2 节 |
| 评分可复算 | ✅ | 5.2 节 |

### 6. 标题与长度
- 用 H1–H4，不用 H5/H6；每层标题下第一句必须是结论句，不是「下面讲……」。
- 长度上限（超了就拆到 04 证据附录，正文只留结论）：

| 文件 | 上限 |
|---|---|
| 01 公司蒸馏 | 300 行 |
| 02 岗位蒸馏 | 150 行 |
| 03 投递方案 | 80 行（A4 一页） |
| 04 证据附录 | 120 行 |
| 05 动作包 | 120 行 |
| 06 面试包 | 150 行 |
| 07 复盘校准 | 80 行 |

### （可选增强）Obsidian callout
Obsidian 里 `> [!warning]` / `> [!danger]` / `> [!tip]` 能渲染成彩色块，降级到普通 Markdown 仍可读。**加分项，不强制**——核心靠上面 6 样。

## 二、HTML / PDF 层（03 投递方案）

03 是对外文档（发 HR / 面试官），走 HTML + Chrome 印 PDF，可以上真颜色。

- **结构**：顶部一句话定位（色块）+ 三层结构 + 90 天 + 指标 + 我的假设 + 一句「为什么现在」。
- **配色**：一个主色（强调标题 / 关键数字）+ 🔴 风险红（仅用于「我的假设」里可能出错处）+ 🟢 达标绿（指标）+ 中性灰（正文）。**不超过 3 色 + 灰。**
- **排版**：A4 一页、页边距 7mm/9mm；表格斑马纹；每个 section 一条色块标题。
- **命令**：`Chrome --headless=new --no-pdf-header-footer --print-to-pdf=<out> file://<html>`；用 `pdfinfo` 验 Pages=1。
- **禁止**：面试问题、内部评价、竞品贬损、薪资谈判、公司「做错了什么」——这些留在对内文件（02/04）。

---

## 三、退稿线（排版不过 = 退稿）

交付前自查，任何一条不满足就退回重写：

1. 没有「一句话结论」引用块（🔴 一票否决）。
2. 风险 / 死门槛 / 待核验没带 🔴 / 🟡。
3. 结论性数字没加粗。
4. 该用表格的地方用了长段文字。
5. 末尾没有交付前对照表。
