# 投递方案模板（≤1 页 A4，对外版）

> 只写能验证的内容；写不出来的，删掉。
>
> **这是给 HR / 用人经理看的文件**：只说"我看到什么、我打算怎么做、我的假设是什么"。
> **不写**：公司战略哪里错了、竞品哪里不行、内部组织问题、薪资谈判、面试问题——这些放 02 岗位蒸馏或 04 证据附录（内部）。

> **排版契约（`references/13_排版规范.md`）**：全文 **≤80 行**（一页 A4）；结论性数字加粗；不写内部判断。

## 对外文档三条禁令（v4.8，违反即退稿）

> [!danger] 这三条会让对方觉得"这是 AI 批量生成的"
>
> **禁令一：不写关于文档本身的任何话。**
> 删掉「对外文档（可发 HR / 面试官）」「不含面试问题 / 内部评价 / 薪资谈判」「内部版 / 对外版」这类标签。文档一开口就解释自己是什么，读者第一反应是"这不是写给我的"。
>
> **禁令二：不出现内部排版语言。**
> 不出现 🔴🟡🟢 色标、`> [!important]`、颜色字典图例、「阅读约定」、「（我的假设）」这类内部标注体系。对外文档只用普通段落、小标题、必要的表格——**看起来像人写的，不像模板渲染的**。
>
> **禁令三：方案没被确认前，不写指标。**
> 「90 天 KPI」「怎么证明我做到了」在首轮方案里是负分：事情还没谈拢就定指标，说明你在表演专业，不是在判断事情。首轮只写**认知 + 顶层设计 + 90 天动作 + 我的假设**。指标留到面试或入职后，等基线摸清再谈。

**一句话**：对外方案要像"一个人看完资料后写的判断"，不像"一个系统按模板输出的报告"。

## 五段结构（v4.9，缺段即退稿）

> 这五段是这份文件的骨架。少一段，对方就会觉得"想法有，但没想清楚"。
> 顺序不能换：**先讲目标 → 再讲问题 → 再讲流程 → 再讲策略 → 最后讲风险**。

### 标题
公司 · 岗位 · 日期 · 假设版

开场一段（≤80 字）：我看完公开信息，先说几个我看到的事实，再说我判断的问题和打算怎么做。

---

### 一、核心目标（这段决定整份文件的高度）

回答一个问题：**这个岗位/这件事，做到什么程度算成功？**

- 不要写"提升用户运营效率""做好私域运营"这种任何公司都适用的话。
- 要写这个业务里**真正的那一件事**：例如"企微不是渠道，是内场——把一次性交易变成可复购的用户资产"；"会员不是用户身份系统，是复购周期管理系统"。
- 给一句**判断标准**：不看什么，看什么。例如"不看上线了多少功能，看同一个用户有没有被认出来、有没有第二次交易"。

> 判据：把公司名替换成同行，这句话还成立 → 说明没写出这家公司，重写。

### 二、问题诊断（2–3 个断点，表格）

| # | 断点 | 表现 | 后果 |
|---|---|---|---|
| A | ___ | ___ | ___ |
| B | ___ | ___ | ___ |
| C | ___ | ___ | ___ |

常见三类断点（按业务挑，不要硬套）：
- **节点未标准化**：流程靠人记，没有输入/输出/时效/质量标准 → 工具不知道支撑什么
- **数据认不出人**：多套 ID，标签靠手工 → 分层是假的
- **AI 停在单点**：只做自动回复，没进流程 → 停掉不影响业务

收尾一句判断：**"这不是功能不够，是流程没被定义清楚"**——这类句子是这一节的价值所在。

### 三、工作流（把流程画成一张表）

| 节点 | 谁主做 | 关键动作 | 时效 | 质量标准 | 工具现在缺什么 |
|---|---|---|---|---|---|
| 1 ___ | ___ | ___ | ___ | ___ | ___ |
| … | | | | | |

- 节点数 5–8 个，覆盖"进来 → 建档 → 首触 → 触达 → 转化 → 服务 → 复购"全链路。
- **最后一列"工具缺什么"是全篇最实用的部分**：它就是需求的来源，也是你入职后第一批要做的事。
- 表下一句话：**"每个节点缺什么，就是一条需求；缺得越多、影响越大的节点，越先做。"**

### 四、核心策略（战略层，2–3 个）+ 执行策略（90 天落点）

**先分清两个词**（这是最容易被判"不专业"的地方）：
- **核心策略** = 战略层的选择，回答"先做什么、按什么顺序做、为什么"；
- **执行策略** = 落地动作，回答"这 90 天具体干什么"。
- 「90 天试点」是执行策略，**不是核心策略**。

核心策略写法：
1. **策略一：___。** 一句话说清，再补一句"为什么是这条"（通常是：没有它，后面的都不成立）。
2. **策略二：___。**
3. **策略三：___。**

> 好的核心策略长这样：「先定节点，再谈工具」「让系统认得出人」「AI 进流程，不进单点」。
> 判据：如果一条策略可以写成"做一个 XX 功能"，那它是动作，不是策略。

执行策略（90 天落点）：

| 阶段 | 做什么 | 产出 |
|---|---|---|
| 0–30 天 | ___ | ___ |
| 31–60 天 | ___ | ___ |
| 61–90 天 | ___ | ___ |

> 每件事都要回答"为什么先做这个"——一句话即可，但必须有。

### 五、风险与应对（表格）

| 风险 | 应对 |
|---|---|
| 一线怕被替代 / 不配合 | ___ |
| 排期排不上 | ___ |
| 数据合规 | ___ |
| 部门墙 | ___ |
| 需求做不完 | ___ |

> 风险写"人的风险"比写"业务风险"更可信：一线抵触、部门墙、排期，才是这类岗位真正会卡住的地方。

## 可选：我的假设（≤3 条）

1. 假设一：___
2. 假设二：___
3. **最可能错的一条**：___（说清如果错了，方案要怎么改）

> 这一节不是自谦，是展示判断力：能说清自己判断的边界，比多写三条策略更可信。
> 若篇幅不够，这条可以并进第五节最后一段，不要单开一节把文件撑到两页。

## 六、PDF 版（默认做，可调）
- **默认规则**：S / A / B 级出 PDF；C 级不出。用户可改（"全出" / "全不出"都听用户）。
- 一条命令：`python3 tools/03_to_pdf.py 03_投递方案.md` —— 自动转 HTML → Chrome 打印 → 校验 Pages: 1，超页会逐档缩字号压回 1 页（内容少的会自动放大到 1.12 倍）。
- 手动版：A4 单页 HTML + Chrome 无头打印 + `pdfinfo | grep Pages` 验证。
- 对外版：不含文档用途说明、内部色标、指标表、面试问题、竞品贬损、薪资谈判
- 面试问题只放 02_岗位蒸馏
